Header Experiments

A live sandbox for open questions about the bar — the ones that are quicker to answer by looking than by describing. The header above this page is the real one, running the shipped code.

The wordmark

The question is not whether “University of Central Florida” belongs beside the mark. It is what the bar actually looks like once the text is gone, and whether anything else in the row moves when it goes. Flip the switch and the bar at the top of this page changes in place — no reload, nothing else on the page touched.

Wordmark beside the mark “University of Central Florida”, stacked on two lines

Press W to flick between the two. The switch is written into this page’s address, so the link you copy opens in the state you were looking at.

What actually changes

Turning the wordmark off clips the text rather than deleting it — it stays in the accessibility tree and in the page’s anchor text, so the link home keeps its name for a screen reader and its description for a crawler. That is the same technique the bar already uses on phones under 390px, so this is a preview of something we could ship, not an approximation of it.

Nothing else in the row needs adjusting, which is worth stating plainly because it is the thing most likely to have gone wrong. The mark and the wordmark sit inside one flex link with a 12px gap between them; a clipped wordmark leaves the flow entirely, so the gap goes with it rather than being left behind as a dent. Measured at 1440px, 980px, 768px and 390px, the mark stays at exactly the same position, the sign-in tray and search keep the same right edge, and the bar keeps its height. The only thing that changes is the text.

Worth watching at narrow widths

  • Under 980px the bar already spends the wordmark when a panel opens, because the tray and the open search field need the room. With the wordmark off, opening either one no longer shifts the logo.
  • Under 390px the wordmark is hidden either way. On a small phone the two states are identical, which is itself an argument worth having: the compact bar is already the one most visitors see.
  • The three shipped layout options work here too — add ?use-full-width=1 or ?use-1200-breakpoint=1 to the address to judge the change against a wider container.

Nothing on this page changes the header any site is embedding. If we decide the bar reads better without the text, it becomes a one-line change in bar.css and a set of new visual baselines.

Adding the next one

This page is built to take more than one question. The experiment above is a single rule keyed off a data-x-* attribute on the header’s host element, held in one stylesheet appended after the bar’s own — so with no attribute set, the bar renders exactly as it ships. A second experiment is another attribute, another rule, and another switch; see the comments in this file.

Page content

Ordinary body copy, here only so the bar is judged sitting above something rather than above nothing. Scroll it under the header, resize the window, open the sign-in tray and the search.

The bar does not follow the page down — it scrolls away with the content, as it always has.
